## 1. 修復 deep-link 返回

- [x] 1.2 [round 2 / F1] `_redirect_to_login` 只在 **idempotent（GET）** 請求時擷取 `next`：非 GET 的受保護請求（例如未登入／session 過期的 `POST /pages/settings/password`、`POST /pages/settings/display-name`）一律省略 `next`，避免登入後把 `next` 以 GET 重播到 POST-only 路由而回傳 `405 Method Not Allowed`，改為 fallback `GET /pages/dashboard`（回復改動前的優雅行為）。`tests/test_pages.py` 新增參數化 `test_protected_post_does_not_store_next` 與 `test_protected_post_round_trip_falls_back_to_dashboard` 鎖定此回歸。
- [x] 1.1 [P] 依「deps.py 改存相對路徑 next」決策，落實「Login redirect preserves the requested page as a relative next」requirement：將 `src/pages/deps.py` 的 `_redirect_to_login` 把 `next` 由 `str(request.url)`（絕對 URL）改存**相對路徑**——取 `request.url.path`，當 `request.url.query` 非空時組成 `path + "?" + query`，再經 `include_query_params(next=<relative>)`。完成後，未登入存取 `GET /pages/settings` 會 302 到 `/pages/login?next=/pages/settings`，且 `next` 不為 `http(s)://…` 絕對 URL；帶 query 的 `GET /pages/dashboard?create_class=1` 其 `next` 保留為 `/pages/dashboard?create_class=1`。驗證：以 `tests/test_pages.py` 新增的相對-`next` 斷言（見 3.1）及 `uv run pytest tests/test_pages.py -q` 通過確認。

## 2. 硬化 next 開放轉址驗證

- [x] 2.1 [P] 依「router.py 硬化 next 驗證器」決策，修改「Browser-based form login endpoint」requirement 的 `next` 驗證：將 `src/pages/router.py` 的 `login_form` 由字串前綴檢查改為兩段式——對 `next` 的 **path 段**（第一個 `?`／`#` 之前）**先拒絕**含 `\`、以 `//` 開頭、含 `:` 者，整串再拒絕含 ASCII 控制字元者，最後要求單一 `/` 開頭且 `urlsplit(next)` 後 `scheme` 與 `netloc` 皆為空；不可單靠 `netloc == ""` 判定安全。authority 檢查刻意只看 path 段，使含 `:` 的合法 query（ISO 時間戳、時間/比值等 deep-link 狀態）能原樣返回。完成後，`next=/\evil.com` 與 `//evil.com`、`http://evil.com`、`https://evil.com` 皆判為不安全（危險字元落在 path 段）→ `safe_next=None` → 登入成功 fallback `GET /pages/dashboard`；合法相對路徑（如 `/pages/settings`、`/pages/dashboard?ts=2026-06-28T12:00:00`）則被允許並原樣返回。驗證：以 3.2 的 open-redirect 向量測試＋ colon-in-query round-trip 測試與 `uv run pytest tests/test_pages.py -q` 通過確認，且 `Location` 不含 `evil.com`。
