## ADDED Requirements

### Requirement: Milkdown WYSIWYG editor for badge description

The badge management page SHALL use a Milkdown editor for the badge `description` field, supporting basic Markdown formatting: bold, italic, unordered lists, ordered lists, links, and inline code. The editor SHALL render in WYSIWYG mode so teachers see formatted output as they type. The `description` field SHALL be stored as Markdown text in the BadgeDefinition document.

#### Scenario: Teacher formats badge description with bold text

- **WHEN** a teacher selects text in the Milkdown editor and clicks the bold button
- **THEN** the editor SHALL wrap the text with `**` markers and display it as bold in the WYSIWYG view

#### Scenario: Badge description stored as Markdown

- **WHEN** a teacher saves a badge with formatted description
- **THEN** the system SHALL persist the description as a Markdown string in the BadgeDefinition document

### Requirement: G2 dual-zone description layout

When a BadgeDefinition is bound to a TriggerRule, the Milkdown editor SHALL display two zones. The upper zone SHALL be a read-only block containing auto-generated condition summary Markdown produced by the WASM `describe()` function. The lower zone SHALL be a free-editing area where teachers write supplementary text. The upper zone SHALL be visually distinguished (e.g., bordered, shaded background) and SHALL NOT be editable by the teacher. When the bound TriggerRule changes, the upper zone SHALL automatically regenerate.

#### Scenario: Auto-generated condition summary displayed

- **WHEN** a teacher binds a badge to a TriggerRule with expression `checkin_streak >= 7 AND submission_count >= 3`
- **THEN** the upper zone SHALL display Markdown generated by `describe()`, containing bullet points for each condition in Traditional Chinese

#### Scenario: Upper zone updates on rule change

- **WHEN** a teacher changes the bound TriggerRule from rule A to rule B
- **THEN** the upper zone SHALL regenerate using `describe()` on rule B's expression

#### Scenario: Teacher freely edits lower zone

- **WHEN** a teacher types supplementary text in the lower zone
- **THEN** the content SHALL be saved as part of the badge description, appended after the auto-generated section

#### Scenario: No upper zone when no rule bound

- **WHEN** a badge has no bound TriggerRule (manual award or code trigger)
- **THEN** the Milkdown editor SHALL display only the free-editing zone without the auto-generated section
