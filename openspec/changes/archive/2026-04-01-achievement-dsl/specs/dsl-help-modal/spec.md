## ADDED Requirements

### Requirement: Help button on DSL editor

The trigger rule editor page SHALL display a help button (question mark icon `[?]`) adjacent to the CodeMirror editor. When clicked, the button SHALL open a modal dialog containing DSL usage documentation.

#### Scenario: Teacher opens help modal

- **WHEN** a teacher clicks the `[?]` button next to the DSL editor
- **THEN** a modal SHALL appear using the existing `window.Modal` system, displaying DSL documentation

### Requirement: Help content generated from Rust crate

The help modal content SHALL be generated by calling the WASM `get_help_content(locale)` function. The returned JSON SHALL contain four sections: `variables` (name, type, description for each built-in variable), `operators` (symbol and description for each operator), `functions` (signature, description, and example for each whitelisted function), and `examples` (complete expression examples with descriptions). The frontend SHALL render this JSON into a formatted modal with section headers, tables for variables and operators, code blocks for function signatures, and syntax-highlighted example expressions.

#### Scenario: Help modal displays variables table

- **WHEN** the help modal is open with locale `tw`
- **THEN** the modal SHALL display a table listing all built-in variables with their names, types (in Chinese: 整數, 字串, 日期時間), and descriptions in Traditional Chinese

#### Scenario: Help modal displays function examples

- **WHEN** the help modal is open
- **THEN** the modal SHALL display each whitelisted function with its signature, a description, and at least one usage example in a code block

#### Scenario: Help modal displays complete examples

- **WHEN** the help modal is open
- **THEN** the modal SHALL display at least three complete expression examples with comments explaining each one
